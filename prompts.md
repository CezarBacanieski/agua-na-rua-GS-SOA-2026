# Registro de uso de IA — Água na Rua

Ferramenta utilizada: Codex. Os pedidos deste registro foram feitos em 11/11/2026 e estão organizados por etapa. A redação foi revisada para melhorar a leitura, preservando a intenção dos pedidos originais; não é uma transcrição literal da conversa.

## 1. Entender a proposta e os requisitos

> Estou fazendo a Global Solution da FIAP com meu grupo. Nossa ideia é o Água na Rua, e quero começar pela entrega de SOA. Leia a proposta, o PDF oficial, o site da GS e o HTML do professor. Me ajude a entender o que precisamos entregar e a organizar o trabalho antes de começar o código. Se encontrar alguma dúvida nos materiais, me avise.

## 2. Definir a linguagem do backend

> Vamos fazer o backend de SOA em Node.js, separado da implementação de C#. Confira se essa escolha está de acordo com o enunciado e mantenha as duas entregas independentes.

## 3. Conferir as orientações da GS

> Confira no PDF oficial se precisamos registrar os prompts utilizados. Veja também como a orientação sobre o vídeo de Testing aparece no documento e ajuste a ficha para deixar claro o que pertence a cada entrega.

## 4. Implementar o backend

> Pode começar a desenvolver o backend de SOA do Água na Rua. Siga os requisitos do PDF e do HTML do professor e organize o código para que o grupo consiga entender e explicar a solução. Quero que o projeto tenha o domínio bem definido, banco de dados, migrações, documentação dos endpoints e testes automatizados.

## 5. Revisar o projeto

> Faça uma revisão detalhada do backend, comparando o que foi implementado com cada critério do professor. Procure falhas no código, nos testes e na documentação. Confira se a aplicação funciona com as instruções do README e aponte o que ainda estiver faltando.

## 6. Publicar no GitHub

> Publique o projeto no repositório agua-na-rua-GS-SOA-2026. Organize os arquivos em commits curtos, em inglês, separados por responsabilidade, como configuração, domínio, persistência, API, testes e documentação.

## 7. Manter o repositório exclusivo de SOA

> Esse repositório é só para a entrega de SOA. Publique apenas o conteúdo necessário do projeto, deixando os materiais gerais da GS na pasta local. O README, os integrantes, a documentação, as evidências e o registro de prompts precisam estar dentro do próprio repositório.

## 8. Conferir a versão publicada

> Confira o projeto que está no GitHub como se fosse o professor avaliando a entrega. Compare os arquivos com os requisitos, teste a execução a partir de um clone novo e verifique se tudo o que é necessário está no repositório. Diferencie os itens comprovados das pendências que ainda dependem do grupo.

## Como a IA foi utilizada

A IA apoiou a leitura dos enunciados, a organização da solução, a implementação do backend, a criação e execução dos testes, as correções, a documentação e a publicação no GitHub. O grupo continua responsável por compreender o código, explicar as decisões e validar a proposta no território escolhido.
