Onde o backend entra na CitizenTech

Cada equipe tem uma CitizenTech só, e cada disciplina constrói uma parte dela. O backend de SOA é a peça que guarda os dados e as regras e que as outras partes consomem pelo contrato: o app de Mobile pode chamar esta API, e a infraestrutura Linux de Operating Systems pode hospedá-la.

O exemplo que atravessa o guia: Alerta Itaverá. Estações medem o nível dos rios de Itaverá, uma cidade fictícia. O backend registra cada leitura, classifica o risco pela cota da estação (normal, alerta ou transbordo) e responde a quem consulta. O exemplo mostra o caminho e é um recorte: sozinho, ele não cobre a rubrica inteira (falta, por exemplo, o CRUD completo de uma entidade). A sua equipe usa o problema dela, com as entidades e as regras dela.

O backend não é a CitizenTech inteira: é o lugar onde moram os dados e as regras. Antes de abrir a IDE, a equipe escreve, em uma página, o que ele precisa guardar e o que precisa garantir.

1 · O problema em uma frase

A mesma frase da ficha da CitizenTech. Ela decide o que entra e o que fica de fora.

"Moradores de áreas de risco de Itaverá não sabem quando o rio vai transbordar."

2 · Os substantivos

O que o backend precisa guardar. Viram as entidades. Três ou quatro bastam.

estação · leitura · alerta · bairro

3 · As regras

O que precisa ser sempre verdade, aconteça o que acontecer. Viram código no domínio e testes.

"cota de transbordo > cota de alerta" · "-999 não é leitura" · "nível ≥ cota → alerta"

E os endpoints?

Saem das perguntas que o app e as outras partes vão fazer. No exemplo: POST /estacoes/{codigo}/leituras (o sensor envia uma leitura) e GET /estacoes/{codigo}/leituras?de=&ate= (o app pergunta o que aconteceu no período), mais o CRUD de uma entidade, que a rubrica pede. 1Estruturação do domínio3,0 pts

É o critério de maior peso junto com o banco: o professor abre o repositório e procura onde estão as regras do problema, e se elas estão protegidas de HTTP e de SQL.

O que é

O conjunto de entidades, valores e regras que descrevem o problema da CitizenTech na língua de quem convive com ele, separado do framework web e do banco.

Por que existe

Quando a regra mora no controller ou na query, ela se repete em cada endpoint, ninguém consegue testá-la sem subir tudo, e uma mudança no banco quebra o negócio. Separar o domínio é o que permite mudar a porta (HTTP) ou o armazém (banco) sem mexer na regra.

Onde a SOA entra

É a lição do DDD que vimos em aula: o serviço termina onde a palavra muda de sentido, e o serviço é dono das suas regras. A API é a porta do serviço; o domínio é o que ela protege.

No exemplo · Itaverá

Estacao sabe classificar um nível pela sua cota e recusa cotas invertidas; a validação do nível recusa o -999 do transmissor em falha. Nenhuma dessas regras está no controller.

import jakarta.persistence.*;
import java.time.Instant;

@Entity
public class Leitura {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(optional = false)
    @JoinColumn(name = "estacao_codigo")
    private Estacao estacao;

    private Instant momento;
    private int nivelCm;

    @Enumerated(EnumType.STRING)
    private NivelDeRisco risco;

    protected Leitura() {}

    public Leitura(Estacao estacao, Instant momento, int nivelCm) {
        // -999 é o código de falha do transmissor: não é uma leitura
        if (nivelCm < 0 || nivelCm > 2000)
            throw new RegraViolada("nível fora da faixa do sensor (0 a 2000 cm)");
        this.estacao = estacao;
        this.momento = momento;
        this.nivelCm = nivelCm;
        this.risco = estacao.classificar(nivelCm);
    }

    public Estacao getEstacao() { return estacao; }
    public Instant getMomento() { return momento; }
    public int getNivelCm() { return nivelCm; }
    public NivelDeRisco getRisco() { return risco; }
}

    NORMAL = "NORMAL"
    ALERTA = "ALERTA"
    TRANSBORDO = "TRANSBORDO"


class RegraViolada(ValueError):

@dataclass(frozen=True)
class Estacao:
    codigo: str
    nome: str
    cota_alerta_cm: int
    cota_transbordo_cm: int

    def __post_init__(self):

        return NivelDeRisco.NORMAL

public class Estacao
{
    public string Codigo { get; private set; } = "";
    public string Nome { get; private set; } = "";
    public int CotaAlertaCm { get; private set; }
    public int CotaTransbordoCm { get; private set; }
    public string? Bairro { get; private set; }          // chegou na 3ª migração
    public List<Leitura> Leituras { get; private set; } = [];

    private Estacao() { }                                 // usado pelo EF Core

    public Estacao(string codigo, string nome, int cotaAlertaCm, int cotaTransbordoCm)
    {
        if (cotaTransbordoCm <= cotaAlertaCm)
            throw new RegraVioladaException("cota de transbordo deve ser maior que a de alerta");
        Codigo = codigo.Trim().ToUpperInvariant();
        Nome = nome;
        CotaAlertaCm = cotaAlertaCm;
        CotaTransbordoCm = cotaTransbordoCm;
    }

    public NivelDeRisco Classificar(int nivelCm) =>
        nivelCm >= CotaTransbordoCm ? NivelDeRisco.Transbordo :
        nivelCm >= CotaAlertaCm ? NivelDeRisco.Alerta :
        NivelDeRisco.Normal;

    // a estação é a raiz do agregado: toda leitura nova passa por ela
    public Leitura RegistrarLeitura(DateTimeOffset momento, int nivelCm)
    {
        // -999 é o código de falha do transmissor: não é uma leitura
        if (nivelCm is < 0 or > 2000)
            throw new RegraVioladaException("nível fora da faixa do sensor (0 a 2000 cm)");

  • Entidades anêmicas: só getters e setters, com a regra espalhada nos controllers.

2Conexão com banco de dados3,0 pts
Os dados precisam sobreviver ao reinício da aplicação e chegar ao banco por uma camada própria, com a credencial fora do código.
O que é
A aplicação lê e grava num banco relacional de verdade, por meio de um ORM ou de repositórios, com a conexão configurada pelo ambiente.
Por que existe
Uma lista em memória some quando o processo reinicia, e uma senha no código vai parar no GitHub. Separar o acesso a dados (repositório) deixa a consulta num lugar só e o domínio livre de SQL.
Onde a SOA entra
Na SOA, cada serviço é dono dos seus dados. Os outros não leem a tabela dele: pedem pela API. É isso que deixa o serviço mudar o esquema sem quebrar ninguém.

O que é

Por que existe
Banco criado à mão não se reproduz; o auto-DDL do ORM (ddl-auto=update, synchronize: true, EnsureCreated, create_all) não guarda a história nem sabe desfazer. Com migrações, qualquer pessoa chega ao mesmo esquema, e cada mudança fica registrada no Git.
Onde a SOA entra
O esquema é interno do serviço e evolui com ele, como o contrato: em versões, uma depois da outra, sem quebrar o que já está no ar.

    [EndpointSummary("Registra uma leitura de nível")]
    [EndpointDescription("Classifica o risco (NORMAL, ALERTA, TRANSBORDO) pela cota da estação.")]
    [ProducesResponseType<LeituraOut>(StatusCodes.Status201Created)]
